Quick start

  1. Pick a module in each column header, for example System Requirements and Software Requirements.
  2. Click + New in a column to write a requirement. It gets an ID such as SYS-0005 automatically.
  3. Drag a requirement onto one in another column to trace them.
  4. Type in a column's filter box to find requirements; the other columns follow the traces.

Concepts

TermMeaning
ModuleA group of requirements at one level, such as Aircraft, System, Subsystem, Component, Software or Verification. Modules are data: create any you need with + Module.
LevelA number that orders modules from the top (0) down. When two requirements are traced, the one in the lower-numbered module is the parent.
PrefixLetters at the start of generated IDs (SW-0001). Each module has its own prefix.
Trace (link)A parent-to-child relationship, for example a system requirement decomposed into software requirements. A requirement can have many parents and many children.
RevisionStarts at 1 and increases whenever the wording or status changes. Earlier versions are kept in the requirement's history.
Source documentsDocuments from the Object Tracker that a requirement comes from. They show as 📄 chips you can click to preview.

Working with columns

  • Start with two columns. + Column adds more (up to six); the area scrolls sideways when they do not fit.
  • ◀ ▶ move a column and ✕ removes it (at least two stay). Your layout is remembered in this browser.
  • Column order matters for filtering: only neighbouring columns are used when filters spread, so put modules in decomposition order, for example Aircraft, System, Software.
  • The same module can be shown in more than one column, for example to compare two filtered views.

Filtering and cross-filtering

Each column has a text box that searches ID, wording, author, status and tags.

You type in…Result
No boxEvery column shows all of its requirements.
One or some boxesThose columns filter by their own text only. Each other column automatically shows only requirements traced to what remains, spreading outward one column at a time. A column between two filtered columns must trace to both.
Every boxAutomatic filtering is off and each column filters independently.

The line above the columns says which mode is active. Clear a box to hand control back to the traces. The count on each column header reads shown / total.

Tracing and highlighting

  • Click a requirement to select it. Directly traced requirements get a solid amber edge. Requirements further up or down the same chain get a dashed, dimmer edge. Siblings are not highlighted. Click again or press Esc to clear.
  • Drag a requirement onto one in a different column to create a trace instantly. Dragging within the same module is ignored.
  • Ctrl+click a requirement while another is selected to add or remove a trace between them.
  • Trace badges on each row show how many requirements it traces to in the neighbouring columns, or a red no … trace badge when there are none. Use these to spot gaps.

Writing and editing

  • Edit: double-click a requirement, or use ✎. Changing the wording or status creates a new revision.
  • Duplicate (⧉): copies a requirement into any module. You choose whether to bring over its tags, source documents and existing traces. The copy starts as Draft.
  • Delete (✕): removes the requirement and every trace to it.
  • Author: choose yourself in the header; new requirements use that author. Add people with + Author.
  • Statuses: Draft, Review, Approved, Obsolete.

Excel import

Click Import Excel and choose an .xlsx file. Use one sheet per module with headers in the first row (capitalisation and punctuation do not matter).

ColumnAccepted headings
Requirement IDID, Requirement ID, Req ID, Identifier, Number. Leave blank to generate one.
Wording (required)Text, Requirement, Requirement Text, Wording, Description, Statement
AuthorAuthor, Owner, Responsible
StatusStatus, State
TagsTags, Labels (comma separated)
ParentsParent, Parents, Traces From, Derived From, Satisfies (IDs, comma separated)
ChildrenChildren, Child, Traces To, Allocated To (IDs, comma separated)

The sheet name selects the module by ID or name. A sheet that matches no module creates one. To choose the module ID yourself, name the sheet with it (for example SYS). Rows whose ID already exists are updated, not duplicated. A summary lists anything skipped, such as traces to IDs that do not exist.

FAQ

How do I show System and Software side by side, or three levels at once? Choose the modules in the column headers. Use + Column for more, ordered top to bottom. Filtering and highlighting work across all columns.
Why did filtering one column empty another? The other column only shows requirements traced to the filtered ones. Either nothing is traced yet (see the red no-trace badges) or the filter matched nothing. Type in the other column's box to turn automatic filtering off for it.
A column between two filtered columns shows nothing. Why? It must trace to both ends. If no requirement links the two matches, the middle column is empty. Clear one filter to see the partial chain.
Which requirement becomes the parent when I drag? The one in the module with the lower level number. If both modules have the same level, the one you dragged is the parent. Check levels in the module list if a trace points the wrong way, and delete and recreate the trace after fixing.
Can I undo a trace? Yes. Ctrl+click the same pair again to remove it. There is no general undo yet.
Can I change a requirement's ID or module? Not yet. IDs and modules are fixed once created so that traces and references stay stable. Duplicate it into the right module and delete the original if needed.
Where is my data stored? In plain JSON files under Data/requirements/ in the Modulyt folder: modules, requirements, links and authors. Edit them by hand if you wish; open pages update within a second. Back them up by copying the folder or committing it to Git.
The 📄 preview is blank. Many websites refuse to be embedded. Use Open in the preview panel, or attach a copy of the file to the document in the Object Tracker (PDFs, images, text and HTML preview inline).
Why do I see no source documents when editing? They come from the Object Tracker. Add documents there first, then tick them in the requirement editor.
Does more than one person work in it at once? Edits save to the file immediately and other open windows update live. There is no sign-in or permission system yet, and two people editing the same requirement at the same time will overwrite each other.
The page will not load or says it is disconnected. The server is not running. Start it with launch.bat or py modulyt.py requirements. The coloured dot at the top right is green while the page is connected.
